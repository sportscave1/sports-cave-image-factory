Implementation
The Analytics UI now reads the existing GA4 exact-report contracts directly.
SEO overview, keyword rankings, opportunities, landing pages, query intelligence
and measurement readers use direct GSC aggregates. Existing OAuth, property
selection, metrics, date/comparison controls, brand/country/device filters,
query normalization, opportunity scoring and owned decisions are reused.
Shopify ledger reads remain separate; Shopify data and integration code are not
mutated. Historical confirmed-revenue dependencies remain retained.

GA4 memory TTL: 20 minutes. GSC memory TTL: 8 hours. Manual Refresh data clears
report caches and changes SEO pagination generation. Cache identity includes
connection revision and selected properties. Cache holds at most 128 entries
and a 32 MiB serialized-payload budget; Python object overhead is additional.
Cold requests are serialized per process to avoid request stampedes. Reporting
HTTP requests do not automatically retry; timeouts, 429 Retry-After and low GA4
property quota establish cooldowns. Explicit refresh cannot reset cooldowns.
There is a per-process limit of 120 outbound reporting requests per minute per
connection scope. Multiple deployed processes still share Google's quota; this
is not a distributed rate limiter. OAuth refresh reuses the existing auth flow.
GSC pagination is capped at eight 25,000-row pages. GA4 contracts retain their
own row limits and have a ten-page guard. Incomplete results are not cached or
presented as complete. GSC top-row/anonymisation limitations are disclosed.
Realtime requests omit unsupported offset/keepEmptyRows/dateRanges fields.
No direct reporting request occurs at module import or normal server startup.

snapshots are not reproducible by today's realtime endpoint.
