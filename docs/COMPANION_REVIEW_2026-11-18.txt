REMAINING FINDINGS / EVIDENCE
upload_companion_page.py: selected queue reads still synchronously await DB;
errors replace content with a warning. History/card rendering is bounded by
20 upload / 100 design / 100 ad rows, but not paged in the UI. Status totals
reflect the loaded window, not necessarily the entire backlog.
worker_health_cache.py Snapshot.read: concurrent callers condition.wait without
a deadline; first refresh blocks on loader; failures lack a last-good fallback.
worker_health.py snapshot + worker_health_api.py snapshot: reads backlog in
500-row chunks, projects all state, then slices 25 rows in API. Growth increases
snapshot cost despite small response pages. Client already has 12s request
abort, visibility-aware 5s/20s refresh, so backend work is the priority.
windows-upload-companion/{worker,staff-queue,design-queue,ad-queue}.js: persistent
journals/receipts protect uncertain sends; design and upload paste/send share a
mutex, while generation can overlap. Queue alarms are 30s. Browser messages can
await an unresponsive content script without an explicit per-call deadline.
Do not blindly retry uncertain ChatGPT sends or reduce alarm periods as a fix.
ads_companion_transfer.py: validates sizes, response identity, cancellation and
lease before import. File bodies are buffered (up to 20 MiB per image), and a
shared import lease serializes work. Preserve deduplication and publication
checkpoints when redesigning transfers.
companion_transfer.py + companion_bandwidth.py: existing process-wide upload
slot, small token bucket, calibration/headroom and streaming are useful safety
foundations. Increasing concurrency alone could harm UI responsiveness.

FOLLOW-UP IMPLEMENTATION - ALL FIVE LOCAL PHASES
The earlier proposed-work section records the initial review. The following
supersedes its implementation status. No commit, push, deployment or live
customer/provider workflow was performed.

1. Resilient queue display
   companion_display.py uses account/revision/permission-scoped snapshots,
   bounded worker and memory budgets, last-good data (maximum 120s), retry delay,
   explicit last-verified timestamps and invalidation after controls. Only the
   visible tab runs. A small visibility component stops refresh timers when the
   browser is hidden and resumes on return. Cached status never authorises an
   action. Read-only queue queries use dedicated connections with local query/
   lock timeouts plus a client cancellation watchdog; the connection factory
   retains its existing 8s connection timeout.
2. Editions scaling
   Background projection preserves the existing authoritative status rules.
   An in-memory SQLite display index serves SQL-filtered 50-row cursor pages,
   bounded deltas, and the legacy 25-row API. Summary counts cover the whole
   projected backlog. Two global refresh slots, single-flight per database,
   exponential retry delay, max-age, 10000-row/16MB per-index limits and a 20s
   projection budget prevent unbounded refresh work. Capacity limits report
   unavailable/stale status rather than silently truncating counts.
   Source SQL also removes a per-product count scan and replaces an OR identity
   join with an equivalent canonical-identity equality join. Duplicate identity,
   approval, source-revision and lease safeguards remain tested.
   Architectural choice: filtering/paging run against the disposable display
   index rather than duplicating complex Python verification rules in production
   SQL. Full authoritative projection still occurs on background refresh; it is
   not constant-cost in backlog size and the index is rebuilt after restart.
3. Browser orchestration
   Companion 1.5.5 bounds content-script requests (readiness 1.5s, status 8s,
   artifact bytes 25s, send 120s). Deadlines free the serial handoff queue but
   retain the durable uncertain-send boundary. Late permits are refused after
   removal. Existing receipt journals, event reconciliation and alarm recovery
   remain in place. Ad collection has one bounded prompt-free fast follow-up
   after a download starts or a verified receipt arrives, instead of always
   waiting for the next 30s alarm. There is no tight idle polling loop.
4. Transfers
   An exact previously recorded ad-file receipt avoids repeat conversion and
   provider upload after a lost acknowledgement. Identity, response ID, content
   hash, size and permissions must match. Conflicting content remains refused.
   CSV/image size gates run before buffering; body consumption has a deadline
   and a two-request bound. Browser blob and streamed downloads enforce matching
   limits. Existing revision-bound PSD reuse, bounded streaming, bandwidth
   headroom, interrupted-transfer recovery and publication gates were retained
   and exercised by their local regression/receiver suites. No speculative
   Photoshop concurrency or quality reduction was introduced.
5. UX and acceptance
   Freshness and stale-state notices, last checkpoint timestamps, bounded
   history/Ads waiting pages, and loaded-window count labels make status honest.
   Design generation no longer advances a percentage merely because time passes.
   Cold Editions reads return a retryable, redacted response. Local browser
   tests cover lazy tabs/composer, outage retention, visibility and mobile width.
