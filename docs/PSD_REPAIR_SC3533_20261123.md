# SC3533 PSD repair and one-click Orders recovery

Owner authorised diagnosis, repair of the Tyson #079/100 and Federer #085/100
artwork, a Companion upgrade, queue submission and this Git/Render release.
Studio task: 20261122-33bceac0; owner: codex-psd-repair-20261123-aff230d3.

## Verified causes

- Both retained preparations reported that exactly one editable number was required.
  Current Photoshop inspection finds Tyson's one editable `No. 12 of 100`, but
  its footer backing is integrated into `Generative Fill 6`, rather than a
  separately named plaque. Federer has two editable numbers and three visible
  plaque layers with repeated names. Its intended production roles are the upper
  number, layer 35, and upper plaque, layer 33.
- The separate Codex repair processes could not provision their local tools.
  They reported that no repair or queue action occurred, but exited normally.
  Companion incorrectly interpreted exit code zero as a successful repair receipt.
- Orders' Repair artwork was a link to another page. Its supplier status poll
  did not include the PSD repair journal, so it showed generic Needs attention
  and concealed the actual repair failure.

## Changes

Orders reads the latest repair journal in one bounded batch. Eligible failed
artwork shows PSD repair; clicking the badge or Repair artwork posts the existing
repair API immediately. Pending clicks are disabled, uncertain network retries
reuse the request UUID, and the server deduplicates active requests per design.
Read-only status refreshes never enqueue. Submitted/completed, invalidated,
cancelled and duplicate allocations cannot be offered as repair actions.

The checklist footer shows the current repair message and retained PSD diagnosis.
Companion requires a structured completed/queued/blocked result instead of
treating a normal Codex exit as success. Failed and missing results remain failed,
their safe diagnostic message is retained by the server, and actual native/JPG
readiness still determines completion.

The two reviewed sources have exact source/hash/revision/layer-ID role evidence.
Native preparation revalidates IDs, names, bounds, visibility, fonts, editability,
edition total, source geometry and source hash. No source PSD or historical layer
is renamed, hidden, flattened or overwritten. A reviewed role fix can resume the
existing guarded native preparation once per source/code revision, then the
repair monitor queues existing valid order allocations and waits for real Ready
JPGs. Explicit operator requests are prioritised over passive catalogue repairs.
Repeated clicks for different units of one design retain every selected allocation.
Explicit Orders repair completion depends on those selected units, so historical
allocations cannot delay the requested order behind a catalogue-wide JPG replay.

Release handover also exposed a retained upload checkpoint that could not report
failure after the deployment changed resumable acceptance generation. Failure
reporting now reauthenticates ownership without allowing a legacy body replay;
a durable failure acknowledgement reconciles the same idle in-memory checkpoint.
Active native workers remain protected, and original packages remain retained.

The live full-range Tyson preparation exposed a separate resize-edge alpha
failure. Native preparation now admits the integrated plaque as the resize
backing when it is the exact visible bottom artwork layer. Its isolated export
must cover the full canvas opaquely; background promotion must preserve every
native composite pixel before enlargement. This applies to future integrated
footer/plaque layouts as well. Partial/transparent plaques, editable text,
different layers, changed pixels and missing colour evidence remain blocked.
The owner subsequently requested deployment without watching production jobs.
