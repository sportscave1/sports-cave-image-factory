FOUR REUSABLE TEMPLATES

A. Collector Welcome: collector introduction, one featured artwork hero and
   collection CTA. No assumption that the subscriber has purchased.
B. Your Collected Artwork: actual purchased artwork (maximum two), exact order
   title, selected variant and verified allocated number when available. Three
   compact collector/account symbols, one View My Collection CTA, neutral order
   progress and conditional account-certificate copy. Suitable as a reusable
   starting point for Post Purchase 1 and 2; copy remains operator-editable.
C. Build Your Collection: up to three matching artworks. Fewer items or just
   the collection CTA when authority, relevance or availability is insufficient.
D. Collector Re-engagement: a smaller previous-purchase image and larger relevant
   recommendations. No automatic discounts, popularity or scarcity assertions.

All bodies use charcoal, warm white and restrained gold; table layouts and
height:auto preserve image proportions. No new logo header, signature, stock
photography, review requests, licensing/autograph claims or fixed edition sizes.
Global header/footer selectors and the compliance footer remain unchanged.

HOW TO USE — EXPLICIT OPERATOR ACTIONS ONLY

1. Open the existing Templates screen. Expand "Collector email templates · V1".
   "Save reusable copy" creates a normal versioned library record only when
   clicked. "Source .txt" downloads the reusable source for Notepad.
2. Open a Welcome, Post Purchase or Win Back email in the existing composer.
   The four built-ins appear in its Templates library without seeding the DB.
3. Choose Use to insert the template. This follows the existing insertion path:
   it replaces a sole empty body, otherwise adds a body section. Review/remove
   unwanted old BODY sections explicitly; insertion does not overwrite a draft
   automatically. Keep the existing header and footer.
4. Open the compact "Personalise Image" popover. Select an existing image block
   or Add image block. Select a source and product count, search and select
   approved artwork, or load and select an approved collection. Manual static
   images use a durable HTTPS JPEG/PNG URL (existing Shopify WebP conversion is
   supported) and an image description. Click Apply image settings to author the
   change. The existing composer save/autosave path then persists that edit.
5. Use the existing desktop/mobile previews. Dynamic examples are clearly
   labelled "Sample preview · fixture artwork". They use public Sports Cave
   artwork, not a real recipient or evidence of stock, ownership or a certificate.
6. Save/edit/copy through the existing library/composer. Product source settings
   are stored inside the HTML section; no customer/order facts are persisted.
   Existing template revision and conflict protection applies.

No new arbitrary real-customer preview lookup was introduced. The existing
authorised checkout preview remains unchanged. Lifecycle previews are fixtures;
actual recipient imagery is freshly resolved only inside the guarded send path.
Do not publish or send these drafts under this local-only authorization.

IMAGE SOURCES AND SAFEGUARDS

Actual Purchased Product: fresh exact-order/customer join; no last-order guess.
Variant image is used only with a matching product identity, otherwise exact
product main image. Missing images/edition facts are omitted. Refunded, partially
refunded, cancelled or otherwise ineligible orders do not render owned artwork.
At most two order lines appear. Multiple unit allocations remain omitted when
the existing allocation reader cannot establish one unambiguous exact allocation.

Related Products: complete verified ownership IDs exclude all previously owned
items, including paginated order lines. Uses authoritative productType or explicit
customer tags of the form interest:<product classification>; it never guesses
interests from a person's name. Exact classification matching is deliberately
conservative and may show fewer artworks.

Featured Collection: the operator selects approved products or a collection.
No approved fallback selection is guessed. With unknown preferences and no
selection, delivery shows the neutral collection CTA without fixture artwork.

Verified New Releases: Shopify createdAt must be within the preceding 30 days
and not in the future. This is a creation-date rule, not an inferred campaign
launch date. The template does not automatically label the item "new".

Verified Bestsellers: requires an operator-selected collection; reads its current
Shopify BEST_SELLING product order, then filters for ownership, relevance and
availability. Does not assert a universal ranking or popularity count.

Static Selected Image: operator-selected durable public image with alt text.
No Image: omits the image block. Static and dynamic blocks coexist.

Recommendations require ACTIVE product status, a valid public product URL,
publishedInContext for the recipient's known country, and a sellable variant.
Unknown recipient country omits recommendations rather than assumes Australia.
Out-of-stock/unpublished/missing-image products are omitted. Product creation,
market publication and inventory facts are fresh at delivery, not preview data.
Edition numbers are only read for exact customer/order/product/line identity;
edition limits are never interpreted as remaining stock.

Recipient results carry their recipient ID and are checked again at rendering.
No private certificate URLs or order URLs enter the email. Unresolved production
image blocks are rejected. Optional Shopify capability outages omit artwork and
retain neutral copy/CTA; identity mismatches fail the existing guarded send path.
The existing deferred-send/idempotency ledger is retained; no duplicate queue,
receipt or certificate-generation mechanism was added.

MY COLLECTION INVESTIGATION AND LOCAL FIX

The configured extension is MySportsCaveCollection.jsx (not the separate disabled
redesign). It reads authenticated Customer Account order certificate metadata.
A purchase alone does not produce a certificate: an absent/pending/unsynchronised
certificate record still yields no certificate card. Permissions can also block
reads. Production customer data was not inspected or modified, so the reported
customer's exact cause has not been confirmed.

Concrete code gap fixed: the extension previously read only the first 50 orders.
It now follows authenticated pagination, up to 20 pages/1,000 orders, and rejects
missing/changed customer identity, incomplete page authority, duplicate orders,
repeated cursors and bound overflow. It never changes to an admin lookup or accepts
an arbitrary customer ID. Existing exact order/customer certificate filtering and
line-item artwork matching remain. Errors show the existing retry/error state,
not a misleading successful empty collection. Missing certificate data is not
fabricated, generated or backfilled. No unrelated storefront UI was changed.

PERFORMANCE

Local rendering measured around 1–2 ms median per template (20 iterations), with
example HTML below 5KB excluding remotely loaded image bytes. Exact metrics and
image load/viewport results are in collector-email-v1/preview-metrics.json.
Preview performs no Shopify requests. Opening the image popover performs no
catalogue requests; Search/Choose collection are explicit lazy actions.
Delivery adds at most 16 logical Shopify requests: two for purchased artwork,
eight order-line continuation pages, one purchase-classification batch, four
selection/ranking requests and one availability batch (up to 48 product IDs).
Actual transport retries remain bounded by the existing Shopify client. Existing
lifecycle order-history verification is additional and unchanged. More than four
distinct selection sets is rejected; incomplete ownership suppresses recommendations.
No production latency benchmark or live delivery was performed.
