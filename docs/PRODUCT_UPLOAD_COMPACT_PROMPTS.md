# Compact Product Upload prompts

The shared Copy Upload Prompt adapter now emits one eight-section brief for the selected mode. Existing saved uploads regenerate through the same adapter. No Dropbox transfers or Shopify writes occur while preparing text.

## Source changes

- `product_upload_compact.py`: ordered formatter, allowlisted saved context, current variant ladder, resolved sport tags, selected-mode rules and custom-template clause migration.
- `product_upload_prompts.py`: existing shared generator entry point and saved template store now feed the compact formatter.
- `product_upload_source.py`: compact saved asset manifest; revision/hash validation stays in the saved source, outside the exported prompt.
- `product_upload_prompt_copy.py`: saved context feeds the generator; context/generator version invalidates cached prompts and rejects stale preparation responses.

Existing clipboard component, layout, image generation, saved files and individual image-copy controls are unchanged.

## Preserved requirements

Tests compare all 16 variant prices, compare-at values, SKU suffixes and size labels against the existing Copy Upload constants, including historical saving/discount labels without recalculation. Inventory, shipping/tax, collections, publication scope, update-price protection and MAP/edition separation are retained. Saved per-product overrides, folder/file identities, save/upload IDs, operation tags and confirmed edition limits are dynamic. Media-only Update preserves existing business settings.

The old source chain combined legacy SOPs, editable templates, pricing/copy/collection/title/sport patches, mode appendices and a separate source/correlation preamble. The new adapter keeps custom template additions once while dropping default scaffolding and known blocking clauses.

Removed: blanket stop-before-write gates, repeated original-file preconditions and permission requests, preflight reports, automatic Draft rollback, duplicate mode descriptions, long copy examples, unrelated sport catalogues and QA matrices. Transfer instructions now describe fresh single-use Dropbox downloads followed by Shopify local-file/imageFile uploads.

## Actual transfer boundary

Tool capability metadata confirms Dropbox download links are single-use (even HEAD consumes them), and Shopify upload_image accepts local imageFile references while sourceUrl requires public HTTPS. The execution environment still needs supported download/network and local-file handoff capabilities. Prompt wording cannot grant missing tools. Report a specific unfinished transfer step if those capabilities are absent; do not fabricate a download or upload.

Deployment is to the existing canonical sports-cave-os service only. The final task response records the verified runtime commit and deployment status. Authenticated production copy/paste is not claimed; browser validation uses a local fixture with production component serving.
